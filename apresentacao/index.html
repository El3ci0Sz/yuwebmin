Contexto

O problema

Como o Yuen Min operava antes do sistema

  • Pedidos manuais (balcão/telefone) — sujeitos a erro de anotação e fila de espera.
  • Cardápio físico/estático — não reflete o que está disponível naquele dia.
  • Montagem de marmita "no olho" — sem controle de limite de porções por tamanho.
  • Fidelidade em papel (cartão de carimbo físico) — fácil de perder, difícil de auditar.
  • Gestão do dia a dia (cardápio, status dos pedidos, financeiro) dependente de controle manual/planilhas.
💡 Sugestão de imagem: foto de um cartão de fidelidade em papel + comanda manual, para contraste com o sistema digital.
Proposta

A ideia e o objetivo

  • Digitalizar ponta a ponta a experiência do restaurante: do pedido do cliente à gestão da cozinha.
  • Cliente monta a própria marmita (bento) escolhendo tamanho, acompanhamentos, bebidas e sobremesas.
  • Pedido chega já estruturado e validado por regras de negócio (limite de porções, endereço, forma de pagamento).
  • Equipe do restaurante gerencia tudo em um painel único: cardápio do dia, status dos pedidos e indicadores financeiros.
  • Programa de fidelidade automático, sem cartão de papel.

Arquitetura

Camadas do backend

Controller — expõe os endpoints RESTrecebe a requisição
Service — regras de negócio (ex.: limite de porções, fidelidade)lógica da aplicação
Repository — acesso ao banco (Spring Data JPA)persistência
Model / Entity — representa as tabelas do bancodados

Atravessando todas as camadas: Security Filter (JWT) valida quem está fazendo a requisição, e Mapper (MapStruct) converte entre Entity e DTO.

Segurança

Como protegemos o sistema

  • Autenticação stateless via JWT — token enviado em cada requisição, sem sessão no servidor
  • Senhas nunca em texto puro — hash com BCrypt
  • Controle de acesso por papel (CLIENTE / ADMIN) — rotas administrativas bloqueadas para clientes comuns
  • CORS configurado por ambiente, liberando só as origens confiáveis
Aprendizado

Principais desafios e soluções

  • Integrar um front-end prototipado a um backend com modelo de negócio próprio — o preço da marmita é fixo por tamanho (não soma de cada item); foi preciso mapear e adaptar as telas para essa regra real.
  • Ambiente Docker + MySQL — problemas de handshake SSL e credenciais desatualizadas em containers recriados; resolvido ajustando a string de conexão e recriando o volume do banco.
  • Compatibilidade Windows/Linux — script do Maven quebrava dentro do container por causa de quebra de linha (CRLF); corrigido com .gitattributes forçando LF.
  • Sincronizar a interface com regras que mudam no servidor (ex.: pontos de fidelidade após um pedido ser concluído) — implementado refetch automático do perfil do usuário.
